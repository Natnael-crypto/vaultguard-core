# Outstanding Tasks

## Bugs to Investigate (Found by Fuzzers)
- [ ] **Bug 1 (VaultTree Merge Rollback Type Confusion)**: When `vault_tree_merge_nodes` fails during a deep copy, it restores `data.sym_key` but forgets to revert `node->type` from `NODE_TYPE_SUBVAULT` back to `NODE_TYPE_KEY`. This causes `vault_node_destroy` to interpret the key pointer as a `SubVault*` and execute the wrong destructor, crashing.
- [ ] **Bug 2 (LRU Cache Iterator Invalidation Double Free)**: `lru_evict_tail()` frees the node's value but does not notify the `SessionManager`'s iterator registry to invalidate open iterators. When `vault_iterator_destroy` is called, it calls `arena_free` on the evicted node, resulting in a double free.
- [ ] **Bug 3 (TLV Decoder Depth Wrap Heap Overflow)**: The `TLVDecoder` tracks `current_depth` as a `uint8_t`. If a payload has >255 nested containers, `current_depth` wraps to 0. The decoder then overwrites `parent_stack[0]` (the root frame), which can cause the parser to write child pointers into arbitrary heap memory, causing a heap overflow.
- [ ] **Bug 4 (VaultAlias Target Use-After-Free)**: `vault_tree_delete_force()` completely destroys a node, but it doesn't notify the `AliasRegistry`. When `alias_resolve()` is later called on an alias pointing to the deleted node, it returns a dangling pointer (use-after-free).
- [ ] **Bug 5 (CipherStream Payload Process Integer Underflow)**: In `payload_process_header()`, if `mac_len + padding_len` > `total_len`, the calculation `total_len - (mac_len + padding_len)` underflows. Since `payload_len` is `uint32_t`, it becomes ~4GB. The subsequent `malloc(payload_len)` allocates a massive buffer and `secure_memset` attempts to zero it, causing OOM or massive CPU stall.
- [ ] **Bug 6 (Key Rotation State Machine Dangling Pointer)**: If `rotation_rollback()` is called, it frees `pending_key_ref` but fails to set the pointer to `nullptr`. Later, `derive_session_key()` checks `if (session->pending_key_ref)` and copies memory from the freed pointer, causing a crash.
- [ ] **Bug 7 (ACL Merge Unrolled Loop OOB Read)**: In `acl_merge_entries_unrolled()`, the loop has `for (; i < count - (count % 4); i += 4)`. Inside the loop, it accesses `entries[i+1]`, `i+2`, and `i+3`. But the loop body also increments `out_idx`. Wait, the bug is that if `count < 4`, `count - (count % 4)` is 0. If `count` is 0, the loop shouldn't run. But wait, `i += 4` is in the increment, and `i += 4` is ALSO in the body. So `i` increases by 8. This causes the loop to skip elements, and if `count` is e.g. 6, `6 - 2 = 4`, so `i=0` runs, `i` becomes 4 in body, 8 in increment, stops. But what if it reads OOB? The bug description says it reads OOB.
- [ ] **Bug 8 (KDF Async Thread Lifetime Issue)**: `kdf_derive_async()` accepts `const KdfParams &params` by reference. It spawns a detached `std::thread` and passes `std::ref(params)`. When the caller of `kdf_derive_async()` returns, `params` goes out of scope, leaving the worker thread reading an expired stack frame (use-after-free on stack).
- [ ] **Bug 9 (Cert Parser Extension Memory Leak)**: In `cert_parse_extensions()`, a `BigInt validation_ctx` is allocated in each iteration. If the extension signature check fails (returning -1), the function exits without calling `bigint_free()`. If called in a loop, this leaks `BigInt` structures until the `SecureArena` exhausts its pool slots, causing a `panic_oom`.
- [ ] **Bug 10 (BigInt Mul Optimized Operator Precedence)**: In `bigint_mul_optimized()`, `if (a->flags & FMT_OPTIMIZED == 0)` is evaluated as `a->flags & (FMT_OPTIMIZED == 0)`, which means `a->flags & 0`. This is always 0. The function incorrectly assumes all Dense BigInts are Sparse, calls `bigint_to_sparse()` and then `sparse_bigint_multiply()`. This calculates the wrong value entirely.
